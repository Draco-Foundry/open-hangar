How to Use Open Hangar

Getting Started
  1. Sign in at robertsspaceindustries.com in this browser. If you're signed out, the card above shows a Log In button.
  2. Hit Scan. The little ▾ arrow next to it lets you scan just Inventory, Buy-Backs or Referrals.
  3. Give it a moment. Big hangars take a minute, and if RSI hiccups, Open Hangar retries on its own.
  4. Rescan whenever your hangar changes. Open Hangar remembers what changed since last time, and puts an amber ! on its toolbar icon when your last scan is a week old.
Browsing Your Hangar
  • Inventory shows every pledge. Search, sort, and switch between Gallery, Compact, List and Market views.
  • The first row of chips picks the kind (Ships, CCUs, Paints…). The second row filters by trait: click once to include, twice to exclude (red), a third time to clear.
  • Click any item for its details: contents, pledge date, store price.
  • The M and G tags mean meltable and giftable: green is yes, red is no.
What's My Hangar Worth?
  • Stats → Value shows your ships at today's store prices next to what you paid, your best deals, and what your CCUs are worth.
  • Melt candidates are pledges you could melt and buy back for the same store credit. Check the ship is actually on sale before you melt anything.
  • The Store page shows every ship's price, whether it's in RSI's store right now, what each of your CCUs is worth, and your wishlist.
  • The Fleet tab adds up cargo, crew and roles, and History charts your melt value over time.
Selling or Showing Off Your Fleet
  • In Inventory, hit Select, click the items you want, give it a title and pick which price to show. Then Download image and post it in Discord or a forum.
  • The Market view is a sale sheet with a "My price" column you fill in. It exports to CSV or an image.
Your Org's Combined Fleet
  • Ask members to open Open Hangar and use Developers → Export HTF. That file is ships only, nothing personal.
  • Import their files on Org Fleet, add your own with Add my fleet, and see every ship, who owns it, and the totals. Export it as a CSV for your org's spreadsheet.
Backups and Switching Browsers
  • Your data stays put when Open Hangar updates.
  • Got alts? Each RSI account keeps its own data. Sign in as the other account and Open Hangar switches over; switch back and your first account's data returns.
  • Uninstalling, or moving to another browser or computer, starts you from empty. So first go to Stats → History → Download backup.
  • To restore, open Developers → Import JSON and pick the file.
Something Not Working?
  • Click Copy error report next to the error (it's also on the Developers page).
  • Paste it in #bug-reports on Discord or in a GitHub issue. It has no personal info in it.
  • Got an idea instead? Post it on the Ideas board.
About and Privacy

Open Hangar is free and open source. It reads your own Star Citizen account using the RSI login you already have in this browser, and saves everything locally.

  • No password, no account, and no server. Nothing you scan leaves your browser.
  • The only other requests are public ones with nothing personal in them: ship pictures from RSI, and ship prices and the game version from star-citizen.wiki.
  • MIT-licensed, so every line is readable on GitHub, and contributions are welcome.

Open Hangar is built as a data tool: it reads a user's own Star Citizen account and organizes it into a clean, structured, local database that other tools and sites can build on. Open source, MIT-licensed, auditable.

How It Pulls Data

RSI uses cookie-based session auth. The extension holds host permission for robertsspaceindustries.com, so its own fetch requests carry the user's existing session cookie — no password, no RSI tab, no server. Server-rendered pages (the hangar) are fetched and parsed locally; nothing is sent anywhere. The fragile bit (RSI's markup) is isolated in parser.js.

The Data Model

Every pledge is normalized to one object:

{ id, name, value, currency,
  contents: [{ kind, label, image }],
  image, containsShip,
  isCCU, ccu: { from, to },
  isAddOn, isCoupon,
  kind }   // ship | ccu | addon | coupon | other

The hangar, buy-backs, account identity + balances (handle, org, rank, Store Credit, UEC, REC — read from the dashboard's embedded JSON and the public citizen dossier), and referrals (code + recruits/prospects via RSI's GraphQL API) are live; the store catalog is planned.

The Export File

One self-describing JSON file, ordered provenance → who → what they own so it maps straight onto a backend table. Schema v2 added the account block (org, rank, balances); v1 had sources only. 

{
  app, appVersion, exportedAt, schemaVersion,   // provenance
  account: {                                    // who this is
    handle, displayName, avatar,
    ueeRecord, enlistedSince, country,
    organization: { name, sid, rank, logo },    // null if none / private
    subscriber, concierge,
    balances: {                                 // storeCredit.value is in CENTS
      storeCredit: { value, currency, symbol, label },
      uec:         { value, currency, symbol, label },
      rec:         { value, currency, symbol, label }
    },
    capturedAt
  },
  sources: {                                    // what they own
    hangar:   { items: [ …pledges… ],  scannedAt },
    buybacks: { items: [ …buy-backs… ], scannedAt },
    referral: { items: {                        // object, not array (one summary)
      current: { recruits }, legacy: { recruits }, prospects,
      recruitsList: [ { handle, moniker, enlistedOn, convertedOn, campaign } ],
      prospectsList: [ … ]
    }, scannedAt }                              // NB: referral code/url are NOT exported
  },
  history: [ { at, items: [ [id, name, value] ] } ]  // scan snapshots (Stats → History)
}

Using It in Your Project

JSON export/import is live — download the whole database (the shape above) to back it up or feed it into your own project; import restores a previous export. Import restores the sources (holdings) and merges the scan history with what's already here; the account block is a read-only snapshot for consumers — the Citizen Card always reflects the live RSI session. Still on the roadmap: an opt-in way for sites you approve to ask the extension for your data directly, instead of exporting a file by hand. It would be limited to a short list of domains you trust, using the browser's externally_connectable messaging channel (note this isn't supported identically across Chrome, Firefox, and Safari).

Saved Accounts

Each RSI account you scan keeps its own data here. Sign in as another account and Open Hangar sets the current one aside and loads that account's last scan instead.

Error Report

Something not working? Copy this report and paste it in #bug-reports on Discord or in a GitHub issue. It has your Open Hangar version, browser, item counts and the recent errors. It doesn't include your handle, referral code or any item names.
